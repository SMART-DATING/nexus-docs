# Проверка требований лабораторных ООП

Дата: 11 октября 2026. Источник: «ООП Лабы 2 семестр-Паблик (2).pdf», 4 страницы. Проверены исходники и документация трёх репозиториев SMART-DATING, результаты тестов и GitHub Actions. Согласование с преподавателем и записи в учебной таблице не подтверждаются наличием кода.

**Вывод:** техническая часть Nexus соответствует основным требованиям к приложению и существенно превосходит этап Hello World. Полное соответствие пока подтвердить нельзя: нужны согласование стека Java/Spring, темы и сценариев, организационные подтверждения, ссылка на Figma и проверка на целевом ноутбуке.

## Сущности: 14 вместо требуемых 10

| JPA-класс | Таблица | Назначение |
| --- | --- | --- |
| UserAccount | users | Участник сервиса |
| ProfileProperty | profile_properties | Поля анкеты и видимость |
| Interest | interests | Тема интересов |
| UserInterest | user_interests | Выбор тем участником |
| Preference | preferences | Предпочтения поиска |
| SessionToken | sessions | Сессия авторизации |
| Reaction | reactions | Симпатия или пропуск |
| PairMatch | matches | Взаимная симпатия |
| ChatMessage | messages | Сообщение |
| Notice | notifications | Уведомление |
| PrivateContext | private_contexts | Личный рассказ |
| ProfilePhoto | profile_photos | Фотография |
| UserBlock | user_blocks | Блокировка участника |
| ChatPreference | chat_preferences | Личные настройки беседы |

Предметные объекты, которые можно обосновать без сессий и связующей таблицы: участник, интерес, фотография, личный рассказ, реакция, взаимная симпатия, сообщение, уведомление. Это восемь объектов; сообщения и уведомления прямо разрешены PDF. Блокировка представляет ещё одно действие участника. Поля анкеты и настройки не нужны для достижения порога семь. Концептуальные связи ERD не везде являются физическими FK: это отдельно раскрыто в [ERD](diagrams/ERD.md).

## Проверки опубликованной версии

- Frontend: 98 тестов / 22 файла и production build успешно. [CI main](https://github.com/SMART-DATING/nexus-frontend/actions/runs/38129194631): сборка, PostgreSQL/backend/nginx, HTTP smoke, H2/Vite и PostgreSQL API-тесты.
- Backend: локально выполнены 27 проверок; 21 PostgreSQL-сценарий локально пропущен из-за отсутствия тестовой БД. [CI main](https://github.com/SMART-DATING/nexus-backend/actions/runs/38129159279) успешно выполняет PostgreSQL-набор отдельно. Локальные пропуски не выдаются за успешные PostgreSQL-тесты.
- Браузер: CTA открывает вход, переход на регистрацию работает, явная регистрация сохранена; свой город идёт первым, другие остаются после пропуска. Карточка и чат имеют одинаковую ширину без горизонтального переполнения на проверенных размерах.
- Оптимизация подбора: на одной локальной базе с 16 анкетами и 38 фото, 100 прогретых запросов, медиана 86,31 → 35,76 мс, p95 152,2 → 63,55 мс. Это измерение прототипа, не нагрузочный тест целевого ноутбука и не обещание времени ответа любой базы.

Наличие тестов не заменяет ревью преподавателя и согласование пользовательских сценариев. Полностью готовый публичный сервис PDF не требует; HTTPS, восстановление пароля и промышленная модерация остаются отдельным планом развития.

## Что закрыть перед сдачей

1. Подтвердить у преподавателя тему, список use cases и Java/Spring/H2 как расширение стека.
2. Проверить учебную Excel-карточку, принятие команды, ссылку и состояние GitHub Project Board; указать календарные сроки в roadmap.
3. Добавить настоящий Figma URL в README или согласовать альтернативные материалы дизайна.
4. Прогнать запуск и демонстрацию на Arch Linux с 8 ГБ ОЗУ; скачать модель заранее, проверить перезапуск и сохранность БД.
5. Подготовить защиту: PM/аналитик — задача и требования; TeamLead/backend — архитектура, БД, приватность и подбор; frontend — пользовательский путь и интерфейс. Затем совместное демо двух аккаунтов: регистрация → рассказ/фото → подбор → взаимная симпатия → чат/уведомление, плюс ошибка ввода и блокировка. Каждый показывает свои изменения и объясняет решения, ограничения и командное взаимодействие.

Переделывать проект на другой backend только из-за списка в PDF пока не требуется: сначала получить решение преподавателя о расширении стека.
