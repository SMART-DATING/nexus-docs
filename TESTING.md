# Проверка текущей семантической версии

## Локальные результаты

Java: 25 тестов, 15 успешно, 10 PostgreSQL-сценариев пропущены без TEST_POSTGRES_URL. Frontend: 33 теста успешно, production build успешно. Сборка единого JAR успешна.

Java покрывает регистрацию/сессии, приватность свойств, like/match/chat/уведомления и конкурентные реакции; возраст и круг Skip; загрузку/декодирование/размер JPEG/PNG; шесть фото, квоту 0/1/2, отсутствие скрытых URL, выдачу без ticket, снижение квоты по ранее выданному URL, перестановку и запрет чужих изменений. Проверены однократный перенос старого аватара и отсутствие восстановления после удаления, параллельные подборки двух аккаунтов без взаимной блокировки галерей.

Контексты: закрытые CRUD, запрет чужого PUT/DELETE, отсутствие текста/embedding в подборе и чужом профиле; изменение текста переставляет рекомендации при одинаковых публичных темах; удаление последнего контекста закрывает подбор с 409.

SemanticEncoderTest использует настоящие фиксированные ONNX-веса: 312 измерений, единичная норма, влияние хвоста длинного текста, точное сравнение с 10 fixtures из tokenizer.json. Три пары русских смысловых парафраз выше посторонних тем: 0.873>0.353 (книги), 0.696>0.429 (походы), 0.770>0.431 (доверие). Это smoke-проверки алгоритма, не статистическая оценка качества дейтинга.

Frontend покрывает API/ошибки/multipart, маршруты чата, жесты и защиту двойной реакции, превью/валидацию/подтверждение фото, запрет отправки черновика рассказа до сохранения, подтверждение удаления рассказа, листание только разрешённых фото и отсутствие img при нулевой квоте.

## Проверено в браузере пользователя

Существующие тестовые аккаунты Артём/Алина и переписки сохранены. Личный рассказ создаёт подборку, собственный текст редактируется и сохраняется после обновления. При 0 фото чужие скрыты, при 1 — один кадр, при 2 — два, остальные отображаются как закрытые. Загрузка PNG с превью, листание второго кадра и перестановка главного работают. Цветовая палитра сохранена. Скриншоты входят в комплект результатов проверки; реальная статистика совместимости не заявляется.

## Воспроизведение

Backend: скачать модель scripts/download-model.ps1/.sh, затем ./mvnw test (Windows .\mvnw.cmd). Для PostgreSQL задать TEST_POSTGRES_URL, TEST_POSTGRES_USER, TEST_POSTGRES_PASSWORD и запустить ./mvnw test -Dtest=PostgresIntegrationTest.

Frontend: npm ci, npm test, npm run build. На запущенном полном стеке: npm run smoke -- http://127.0.0.1:8088; для H2/Vite — адрес 5173. Smoke создаёт новые тестовые аккаунты; они остаются в базе.

GitHub Actions frontend строит PostgreSQL/backend/nginx, проверяет legacy category и HTTP smoke, затем H2/backend/Vite. Backend workflow отдельно запускает H2 и PostgreSQL API-тесты. Текущий полный прогон: https://github.com/SMART-DATING/nexus-frontend/actions/runs/37899600430 — успешно: 33 frontend-теста, Docker PostgreSQL/nginx и H2/Vite, все 10 дополнительных PostgreSQL API-тестов без пропусков.

## Границы проверки

Локально PostgreSQL не считается проверенным только из-за успешной H2. Docker проверяется в CI; доступ из локальной среды к Docker Engine ограничен. Нагрузочных испытаний, независимого корпуса для ML и пользовательского исследования нет. Публичный запуск требует дополнительной подготовки.

## Первое знакомство и голос

Компонентные сценарии: выбор и пропуск тем, профиль до интервью, тематические и общие вопросы, возврат к ответу, пропуск всех вопросов, проверка текста, сохранение и повтор после ошибки. Повтор после сбоя обновления профиля не создаёт вторую историю. SpeechRecognition проверяется управляемым mock: согласие до start, промежуточный и финальный результат без дублирования, остановка, запрет микрофона, текстовая альтернатива, очистка при уходе. Эти проверки не заменяют проверку реального микрофона и сервиса конкретного браузера.

### Проверка интерфейса 2026-10-09

В локальной сборке пройдены регистрация нового тестового аккаунта, выбор книг / музыки / психологии, заполнение анкеты, вопросы по выбранным темам, возврат с сохранением ответа, пропуск вопроса и сохранение личного рассказа. Рассказ доступен в собственном профиле; подборка открывается. Проверены экран согласия на голосовой ввод и продолжение текстом без включения микрофона.

При фактическом viewport 480 × 844 кнопки пропуска и лайка находятся в видимой области над нижней навигацией, не перекрыты; пропуск переключает анкету. PNG загружается с предварительным просмотром, сохраняется как первое фото и открывает один кадр других анкет.

Выявлено накопление старых заголовков при смене вопроса. Исправлены конфликтующие ключи компонентов; все 33 теста и production build прошли с проверкой единственного заголовка. Повторная проверка после перезапуска успешна: на переходах вперёд, назад и к итоговому рассказу отображается один заголовок, ответы сохраняются. Повторное интервью создаёт один новый рассказ; после обновления страницы оба собственных рассказа и ранее загруженное фото сохранены. Реальное распознавание речи и ширина меньше 480 px в этой сессии не проверены.

## 2026-10-09 — Упрощённый интерфейс

36 frontend-тестов и production build успешны. Новые проверки подтверждают сохранение черновика между вкладками профиля и управление вкладками с клавиатуры. Обновлены проверки раскрытия анкеты и основных маршрутов. [Полный CI](https://github.com/SMART-DATING/nexus-frontend/actions/runs/37905765804): сборка, PostgreSQL/nginx и H2/Vite успешны.

В браузере проверены реальные viewport 1200 × 800, 480 × 844 и 480 × 700. Кнопки выбора полностью видимы; на узких экранах располагаются выше нижней навигации, горизонтального переполнения нет. Пропуск и лайк переключают анкету, подробности раскрываются и сворачиваются. Несохранённое имя сохраняется при переключении вкладки и не отправляется на сервер; ранее сохранённые фото и личные рассказы доступны в своих разделах.

В существующем тестовом чате новое сообщение отправлено и сохранено. «Все чаты» закрывает разговор; обновление страницы оставляет список на `#matches`. Колокольчик открывает уведомления. Вкладки фото и закрытых рассказов сохраняются после обновления страницы; компонентный тест также проверяет прямой путь к управлению фото. Ошибок JavaScript в проверенных сценариях не зафиксировано. Приёмка выполнена через Vite с действующим API; готовый JAR содержит ту же production-сборку, его запуск после обновления отдельно не проверен.

Исследование с новыми пользователями, реальный микрофон, физический телефон с экранной клавиатурой и ширина 320 px ещё не проверены. Основания решений и план пользовательской проверки — в [описании интерфейса](design/interface.md).
