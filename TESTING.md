# Проверка приложения

Проверки разделены по границам системы: клиент, сервисы/API, реальный HTTP-путь и ручной пользовательский сценарий. Рабочую базу для них использовать не нужно.

## Автоматические проверки

| Уровень | Где находится | Что подтверждает |
| --- | --- | --- |
| Frontend | `nexus-frontend/src/*.test.ts(x)` | Навигацию, формы, интервью, сохранение, галереи, восстановление медиа, жесты, диалоги, ожидание и UI чатов |
| API / H2 | `ApiIntegrationTest` | Сессии и доступ, данные анкеты, контексты, фильтры, порядок города/score, циклы Skip, квоту фото, match, прочтение, блокировки и экспорт |
| PostgreSQL | `PostgresIntegrationTest` | Те же интеграционные сценарии на PostgreSQL; наследует API-тесты и включается переменными окружения |
| Модель | `SemanticEncoderTest` | Токенизацию, 312 измерений, несколько русских смысловых примеров и влияние длинного текста |
| Запуск и старые базы | `HttpStartupTest`, `DemoStartupTest`, `LegacyMigrationTest`, `LegacyInterestStartupTest` | HTTP-запуск, отсутствие автоматического возврата старых анкет и перенос прежних полей |
| Сквозной HTTP | `nexus-frontend/scripts/smoke.mjs` | Регистрацию, профиль, фото, рассказы, очередь, взаимность, чат, прочтение, экспорт, скрытие, блокировки и выход через настоящий HTTP |

### Frontend

Из `nexus-frontend`:

```sh
npm ci
npm test
npm run build
```

Компонентные тесты выполняются с jsdom. Production build проверяет TypeScript и сборку, но не заменяет визуальную проверку браузера.

### Backend и модель

Из `nexus-backend`, Windows:

```powershell
pwsh -File scripts/download-model.ps1
.\mvnw.cmd verify
```

Linux/macOS:

```sh
sh scripts/download-model.sh
sh ./mvnw verify
```

Модель требуется: без весов модельный тест должен сообщить проблему, а не считаться проверкой с заглушкой. H2-сценарии используют изолированные базы в памяти. XML-отчёты Maven находятся в `target/surefire-reports`.

### PostgreSQL

Создайте **отдельную тестовую БД**, не рабочую. В PowerShell:

```powershell
$env:TEST_POSTGRES_URL='jdbc:postgresql://127.0.0.1:5432/nexus_tests'
$env:TEST_POSTGRES_USER='nexus'
$env:TEST_POSTGRES_PASSWORD='пароль_тестовой_базы'
.\mvnw.cmd test '-Dtest=PostgresIntegrationTest'
```

Если TEST_POSTGRES_URL отсутствует, этот набор пропускается. Такой запуск не следует описывать как успешную проверку PostgreSQL.

### HTTP smoke

После запуска из [RUNBOOK](RUNBOOK.md), из `nexus-frontend`:

```sh
npm run smoke -- http://127.0.0.1:8088
```

Для Vite замените адрес на `http://127.0.0.1:5173`; для единого JAR — `http://127.0.0.1:8080`. Скрипт создаёт тестовые записи: запускайте его на отдельной среде. Он проверяет запросы и права, а не расположение элементов в настоящем браузере.

## CI

[Backend checks](https://github.com/SMART-DATING/nexus-backend/actions/workflows/ci.yml) выполняет Maven verify и отдельный PostgreSQL-набор. [Frontend checks](https://github.com/SMART-DATING/nexus-frontend/actions/workflows/ci.yml) выполняет компонентные тесты и build, собирает PostgreSQL/backend/nginx и проверяет HTTP smoke; затем проверяет H2/backend через Vite. Есть сохранение прежней обязательной категории интересов.

В отчёте проверки указывайте commit SHA, дату, среду, команды, pass/fail/skip и ссылку на запуск CI. Старое количество тестов и старые скриншоты не являются текущим статусом. Изменение только Markdown не означает повторную проверку всех функций приложения.

## Ручная приёмка

Используйте два вымышленных аккаунта в отдельных браузерных сессиях. Рекомендуемые размеры: 1440×900, 1366×768, 390×844 и 320×740 CSS px; дополнительно короткое окно и реальный телефон с экранной клавиатурой.

| Шаг | Действие | Ожидаемый результат |
| --- | --- | --- |
| 1 | Открыть главную, пройти секции вниз и вверх до краёв | Шапка и переходы не ломаются; FAQ открывается по одному и закрывается при уходе из вида |
| 2 | Открыть основной CTA, затем регистрацию; ввести разные пароли | Сначала вход, есть переход к регистрации; несоответствие паролей понятно |
| 3 | Пройти темы и сведения, пропустить вопрос, вернуться | Черновик восстановлен; прогресс начинает с 0 завершённых |
| 4 | Попытаться сохранить короткий рассказ, затем исправить | Показана причина; корректный текст сохраняется, предлагается фото |
| 5 | Выбрать фото, отменить, подтвердить; заменить и удалить | Диалог относится к конкретному кадру; отмена ничего не меняет |
| 6 | Проверить нулевую и увеличенную квоту другого аккаунта | Видны только разрешённые кадры; уменьшение квоты закрывает прежние лишние URL |
| 7 | Сделать подходящие анкеты разных городов и сходства | Свой город первым, внутри групп score ↓; низкий score не пропадает |
| 8 | Выполнить Skip/Like кнопкой, свайпом и стрелками | Одна реакция на действие; вертикальное движение и просмотр фото не реагируют |
| 9 | Задержать/оборвать запрос следующей выдачи в DevTools | Карточка сохраняется; текст ожидания только после 2 с; ошибка допускает повтор |
| 10 | Поставить встречные Like, открыть чат и отправить сообщение | Одна взаимность, полноэкранное появление, сообщение сохранено; счётчик снимается в открытом чате |
| 11 | Закрепить, отметить, очистить и скрыть беседу | Действия личные; история собеседника сохраняется; новое сообщение возвращает чат |
| 12 | Включить паузу, затем блокировку | Пауза сохраняет старый чат; блокировка закрывает его обеим; встречная блокировка не снимается чужой отменой |
| 13 | Выгрузить данные, выйти, повторить защищённый запрос | JSON не содержит секретов/полученных сообщений; отозванный токен не работает |
| 14 | Пройти клавиатурой, включить reduced-motion | Действия доступны, диалоги возвращают фокус, декоративное движение выключено |

## Что остаётся отдельной проверкой

Реальная работа микрофона в разных браузерах, доступность экранным диктором, пользовательская полезность рекомендаций, нагрузка большой аудитории и восстановление резервной копии на целевом оборудовании. Успех фиксированных примеров модели и эмуляция экрана не доказывают эти свойства.
