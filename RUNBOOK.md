# Запуск и обслуживание

Есть три варианта: разработка с двумя процессами, Compose с PostgreSQL и сборка единого JAR. Все команды ниже выполняются из указанных каталогов; рабочие базы не нужны для проверки чистого запуска.

## 1. Подготовить исходники

Клонируйте репозитории рядом, сохранив имена каталогов:

```sh
git clone https://github.com/SMART-DATING/nexus-backend.git
git clone https://github.com/SMART-DATING/nexus-frontend.git
git clone https://github.com/SMART-DATING/nexus-docs.git
```

Используется `main`. Для работы из исходников нужны Git, **JDK 21**, **Node.js 22.20+ из ветки 22 либо 24.12+ из ветки 24** и npm; Maven скачивает Wrapper. На Windows инструкции используют **PowerShell 7** (`pwsh`). На Linux нужны `curl` и `sha256sum` для загрузки и проверки модели. Для Compose достаточно Docker с Compose v2 и Linux containers. Первый запуск требует сети для зависимостей, образов и модели. После загрузки модель обрабатывает рассказы локально, без внешнего API и ключа.

## 2. Разработка без Docker

### Backend — первое окно

Windows, PowerShell 7, из `nexus-backend`:

```powershell
pwsh -File scripts/download-model.ps1
.\mvnw.cmd clean package
java -jar target/nexus-backend-0.0.1-SNAPSHOT.jar --spring.profiles.active=local
```

Linux, из того же каталога:

```sh
sh scripts/download-model.sh
sh ./mvnw clean package
java -jar target/nexus-backend-0.0.1-SNAPSHOT.jar --spring.profiles.active=local
```

Ожидается `Started NexusApplication`. API: `http://127.0.0.1:8080/api/v1/health` → `{"status":"ok"}`. Профиль local использует H2 в `nexus-backend/data/nexus.mv.db`. Health подтверждает HTTP-путь, но не наличие модели; её готовность видна после входа в `GET /api/v1/contexts/me` как modelAvailable.

### Frontend — второе окно

Из `nexus-frontend`:

```sh
npm ci
npm run dev
```

Откройте `http://127.0.0.1:5173/`. Vite проксирует `/api` на `127.0.0.1:8080`. Backend без встроенной React-сборки сам по себе не обязан показывать интерфейс на порту 8080. `npm run preview` использует 4173 и тот же API-прокси; это проверка собранного клиента, не замена backend.

## 3. Compose: весь сайт и PostgreSQL

Из `nexus-docs`:

```sh
docker compose up -d --build --wait --wait-timeout 180
docker compose ps
```

Сайт: `http://127.0.0.1:8088/`. Состав: nginx + React → backend → PostgreSQL 16. Postgres и backend в этом compose не публикуют свои порты на хост; nginx доступен только через loopback. Dockerfile backend загружает проверенные веса во время сборки.

```sh
docker compose logs -f backend
docker compose down
```

`down` останавливает сервисы, сохраняя именованный volume БД. **Не добавляйте `-v` для обычной остановки:** это удаляет данные. Одинаковые по назначению compose-файлы в разных репозиториях создают отдельные проекты/volumes; выберите один и используйте его последовательно.

Отдельный backend + PostgreSQL: `docker compose up -d --build --wait` из `nexus-backend`, API на 8080 и Postgres на 5432. Только backend с H2: `docker compose -f compose.h2.yaml up -d --build --wait`, данные в отдельном H2 volume. Эти варианты сами не собирают React.

## 4. Единый JAR с интерфейсом

Из `nexus-docs`:

```powershell
pwsh -File build-demo.ps1
```

Либо Linux:

```sh
sh build-demo.sh
```

Скрипт собирает React, загружает модель, выполняет backend-тесты и встраивает клиент в JAR. После сборки перейдите в `nexus-backend` и запустите:

```sh
java -Xms64m -Xmx512m -jar target/nexus-backend-0.0.1-SNAPSHOT.jar --spring.profiles.active=local
```

Сайт и API будут на `http://127.0.0.1:8080/`. При переносе нужны JAR, Java 21 и каталог `models/rubert-tiny2` с model.onnx/vocab.txt; каталог можно указать через `NEXUS_MODEL_DIR`. Путь H2 по умолчанию зависит от текущего рабочего каталога. Для постоянных данных задавайте абсолютный DATABASE_URL или запускайте из одного каталога.

Готовые локальные комплекты могут содержать START.cmd/START.ps1/START.sh. Это внешняя упаковка, а не файлы данных репозитория; здесь описан воспроизводимый способ сборки из исходников. Конкретные имена датированных JAR не являются постоянным контрактом проекта.

## 5. Конфигурация

| Переменная | По умолчанию / назначение |
| --- | --- |
| `SPRING_PROFILES_ACTIVE` | local по умолчанию; postgres — внешний PostgreSQL |
| `PORT` | 8080 |
| `BIND_ADDRESS` | 127.0.0.1 при локальном запуске; Dockerfile задаёт 0.0.0.0 внутри контейнера |
| `NEXUS_MODEL_DIR` | `./models/rubert-tiny2` относительно рабочего каталога |
| `DATABASE_URL` | local: `jdbc:h2:file:./data/nexus;MODE=PostgreSQL;DB_CLOSE_ON_EXIT=FALSE`; postgres: `jdbc:postgresql://127.0.0.1:5432/nexus` |
| `DATABASE_USER` | local: sa; postgres: nexus |
| `DATABASE_PASSWORD` | local: пустой; postgres/compose: локальное значение nexus-local-dev |
| `TEST_POSTGRES_URL`, `TEST_POSTGRES_USER`, `TEST_POSTGRES_PASSWORD` | Отдельная БД для интеграционных проверок, см. TESTING |

Обычный запуск создаёт справочник интересов и сохраняет существующих пользователей; старые рисованные анкеты не возвращаются. `NEXUS_DEMO=true` сам по себе не заполняет базу такими профилями. Отдельное свойство `nexus.demo.seed-illustrated=true` оставлено для изолированных тестов; для обычной демонстрации оно не требуется.

## 6. Проверить основной путь

Создайте два вымышленных аккаунта в разных браузерных сессиях. У обоих заполните данные, сохраните рассказ и добавьте фото; для простого сценария задайте совместимые предпочтения. Проверьте выдачу, встречные Like, чат, прочтение, блокировку и выгрузку. Копия рабочей базы и реальные чужие фотографии для этого не нужны. Подробный сценарий — в [TESTING.md](TESTING.md).

## 7. Подключиться к БД

**H2:** остановите backend, затем используйте H2 Embedded v2 с драйвером 2.3.232. Пример JDBC URL с абсолютным путём:

```text
jdbc:h2:file:C:/path/to/nexus-backend/data/nexus;MODE=PostgreSQL;IFEXISTS=TRUE
```

Пользователь sa, пароль пустой, если конфигурация не изменялась. Расширение `.mv.db` в URL не добавляется. IFEXISTS предотвращает случайное создание другой пустой базы. Отключите DBeaver перед повторным запуском backend: текущий embedded-режим не допускает одновременное открытие файла отдельными процессами.

**PostgreSQL:** при отдельном backend compose доступен 127.0.0.1:5432, база/пользователь nexus; пароль соответствует DATABASE_PASSWORD. В полном compose из docs порт БД наружу не опубликован; для SQL используйте `docker compose exec postgres psql -U nexus -d nexus`.

## 8. Резервная копия и восстановление

- H2: корректно остановите backend и скопируйте весь каталог data. Для проверки восстановления используйте отдельный каталог/копию, а не единственный рабочий файл.
- PostgreSQL: используйте `pg_dump`/`pg_restore` согласованной версии и отдельно проверьте восстановление в новой БД. Прямое копирование файлов работающего volume не является этой процедурой.
- Фотографии находятся в БД. Веса модели воспроизводимо загружаются скриптом, но их ревизия должна соответствовать версии приложения.
- Собственная JSON-выгрузка из UI — данные одного участника; она не заменяет резервную копию БД и не имеет функции импорта.

## 9. Доступ друзьям

Loopback-адрес доступен только на компьютере, где работает сервер. Для временной демонстрации можно направить HTTPS-туннель на единый JAR `http://127.0.0.1:8080` либо на compose-сайт `http://127.0.0.1:8088`. Друзьям отправляют публичный URL туннеля; компьютер, приложение и туннель остаются включёнными.

Туннель не открывает прямой доступ к H2/PostgreSQL и не является постоянным размещением проекта. Авторизация и все правила приложения сохраняются. Сетевой маршрут зависит от выбранной среды; готового публичного адреса в репозитории нет.

## Диагностика

| Симптом | Что проверить |
| --- | --- |
| Сайт на 5173 не получает данные | Работает ли backend на 8080 и отвечает ли health; не перепутан ли режим запуска |
| На 8080 нет интерфейса | Собран ли единый JAR; при раздельной разработке открывайте 5173 |
| 503 при сохранении рассказа | Оба файла модели, NEXUS_MODEL_DIR, modelAvailable; повторите скрипт загрузки |
| Health ok, но модель не готова | Health не проверяет веса. При отсутствии файлов остальные API могут запускаться |
| Database may be already in use | Другой backend или DBeaver держит H2-файл; остановите/отключите его |
| После смены каталога данные исчезли | Относительный путь H2 открыл другую базу; проверьте рабочий каталог и DATABASE_URL |
| Пустая подборка | Заполненность, рассказ, фото в UI, предпочтения, пауза, блокировки и предыдущие Like/Skip |
| Фото перестало открываться | Истёк ticket, изменились квота/порядок/версия/видимость; обновите анкету |
| Растёт использование памяти/CPU | Разделите Java, браузер и контейнеры в наблюдении; проверьте, не запущено ли несколько копий. Heap не включает native ONNX |
| Контейнеры долго собираются | Первая загрузка Maven/npm/образов и модели; смотрите build/logs, а не только HTTP health |

Границы эксплуатации — в [STATUS](STATUS.md), [нефункциональных требованиях](requirements/non-functional-requirements.md) и [roadmap](roadmap.md).
