# Состояние реализации

Nexus — работающий веб-прототип сервиса знакомств. Основной пользовательский путь реализован: от регистрации и личного рассказа до подбора, взаимной симпатии и переписки. Этот документ отделяет доступные возможности от планов.

## Реализовано

| Область | Доступное поведение |
| --- | --- |
| Аккаунт | Регистрация с email, логином и подтверждением пароля; вход по логину или email; выход и сессии сроком 24 часа |
| Первое знакомство | До десяти публичных интересов, основные сведения, три подготовленных вопроса с пропуском, редактирование результата, переход к фотографиям |
| Личные истории | До двенадцати отдельных рассказов; создание, изменение и удаление только владельцем |
| Подбор | Локальная текстовая модель, свой город первым, сортировка по сходству внутри групп, без минимального процента; возрастной фильтр и взаимный фильтр пола |
| Фотографии | До шести JPEG/PNG, предварительный просмотр и подтверждение, замена, удаление и порядок; взаимное ограничение числа доступных снимков |
| Реакции | Like и Skip кнопками, свайпом или клавиатурой; повтор пропущенных после исчерпания новых подходящих анкет |
| Общение | Один чат после встречных Like; история, отправка, непрочитанные, личные закрепление/очистка/скрытие и уведомления внутри сайта |
| Контроль доступа | Собственная видимость полей, пауза показа анкеты, двустороннее действие блокировки, выгрузка собственных данных |
| Интерфейс | Адаптивные экраны, маршруты браузера, сине-фиолетовый движущийся фон, режим уменьшенного движения |
| Запуск | H2 без отдельного сервера БД; PostgreSQL и nginx через Docker Compose; сборка React в единый JAR |

## Важные границы

- Интерфейс открывает карточки знакомств после основных данных, сохранённого рассказа и хотя бы одного собственного фото. Backend исторически допускает подбор без фото, выдавая нулевую квоту чужих изображений.
- Пол проверяется в обе стороны: участники должны соответствовать выбору друг друга. Возраст кандидата проверяется по диапазону смотрящего; встречный возрастной диапазон сейчас не применяется.
- Город — текстовое поле, а не координаты. Приоритет своего города не является поиском по расстоянию и не повышает процент сходства.
- Истории закрыты от других участников. Администратор БД технически имеет доступ к их текстам и фотографиям; сквозное шифрование не реализовано.
- Голосовой ввод использует возможности браузера. Его сервис распознавания может обрабатывать звук удалённо. На сервер Nexus отправляется подтверждённый текст, а не аудиозапись.
- Скрытие анкеты сохраняет существующие чаты. Блокировка ограничивает доступ обеих сторон и к существующему чату.
- Удаление чата в интерфейсе скрывает его только у текущего пользователя. Новое сообщение возвращает его в список; физического удаления переписки нет.
- Схема БД обновляется Hibernate. Временные разрешения на фотографии находятся в памяти одного backend-процесса.

## Ещё не реализовано

Восстановление пароля, подтверждение email, удаление аккаунта, жалобы и модерация, защита от массовых запросов, WebSocket/push, геолокация, интеграция Telegram, анализ внешности, обучение модели на реакциях и коммерческие функции.

Это направления развития, а не скрытые возможности текущей сборки. Приоритеты и основания — в [roadmap](roadmap.md).

## Что подтверждено проверками

В репозиториях есть автоматические проверки клиента, API на H2/PostgreSQL, обработки фотографий, прав доступа, конкурентных реакций и реального HTTP-пути через Vite/nginx. Проверка качества модели включает несколько фиксированных смысловых примеров и токенизацию; это не исследование качества знакомств на реальных пользователях.

Актуальные команды, границы и ссылки на CI: [TESTING.md](TESTING.md). Метрики удержания, качество рекомендаций на целевой аудитории и производительность при массовой нагрузке пока не измерены.
