# Сценарии и негативные проверки

1. **Регистрация:** открыть форму, ввести email и пароль; после успеха перейти к заполнению профиля. Дубликат email — 409, некорректные поля — 400.
2. **Профиль:** сохранить имя, bio, дату рождения, город, 1–10 интересов; задать публичность. Возраст меньше 18 лет, неизвестный интерес или пустое имя отклоняются.
3. **Подбор:** открыть знакомства; изменить возрастные предпочтения; увидеть общие интересы и процент Жаккара. Неполный профиль требует заполнения, отсутствие кандидатов отображается как нормальное пустое состояние.
4. **Симпатия:** A ставит like B; B ставит like A; создаётся единственный match. Повторная реакция — 409; самореакция — 400. Skip убирает профиль из последующей выдачи.
5. **Чат:** участник выбирает match или открывает `/match/{matchId}`, отправляет текст; второй участник получает его при опросе сервера. Чужой участник получает 403, пустой текст — 400. Текст отображается как текст, без HTML.
6. **Уведомление:** открыть раздел, выбрать новое событие; оно помечается прочитанным и открывает соответствующий чат. Чужой ID — 403.
7. **Выход:** сессия удаляется на сервере, токен убирается из вкладки. Повторное использование токена — 401. При истечении сессии интерфейс возвращается к форме входа.

Для воспроизводимой проверки см. RUNBOOK.md и TESTING.md. Исторические сценарии с JWT находятся в archive/ и не описывают текущую реализацию.
