# Функциональные требования

Требования ниже описывают реализованное поведение текущей версии. Для каждого указана наблюдаемая приёмка. Смысл терминов — в [глоссарии](glossary.md), пользовательский контекст — в [сценариях](use-cases.md).

## Аккаунт и подготовка

| ID | Требование | Критерий приёмки |
| --- | --- | --- |
| FR-01 | Гость может зарегистрироваться и войти | Форма регистрации требует email, уникальный логин, пароль и его подтверждение; при несовпадении или занятости данных причина показана. Вход принимает логин или email |
| FR-02 | Участник может завершить текущую сессию | Выход отзывает текущий токен; новый запрос с ним возвращает 401. Срок сессии — 24 часа |
| FR-03 | Первое знакомство направляет к готовой анкете | После регистрации доступны темы, основные сведения и вопросы. Можно отложить заполнение; список незавершённых действий ведёт к нужному экрану |
| FR-04 | Участник управляет основными сведениями и видимостью полей | Сохраняются имя, подпись, дата рождения и город. Имя обязательно публичное; дата даёт возраст 18–100; чужие скрытые поля отсутствуют в ответе API |
| FR-05 | Участник выбирает до десяти публичных интересов | Допустимы только значения серверного справочника; пустой набор разрешён. Интересы видны в анкете |
| FR-06 | Участник задаёт свой пол и предпочтения | Пол: `male`, `female`, `other`, `unspecified`; предпочтение: `all`, `male`, `female`, `other`; возраст 18–100 и min ≤ max. Пол возвращается только владельцу |
| FR-07 | Некс помогает сформировать личный рассказ | Три подготовленных вопроса зависят от интересов, доступны возврат и пропуск. Прогресс отражает 0–3 завершённых шага; итог редактируется до явного сохранения |
| FR-08 | Голос дополняет текстовый ввод при поддержке браузера | До микрофона показано пояснение; отказ или ошибка оставляют текстовый ввод. Аудио на сервер Nexus не загружается |
| FR-09 | Участник создаёт, редактирует и удаляет свои истории | Не более 12 рассказов; название 1–60, содержимое 20–6000 символов после удаления внешних пробелов. При коротком тексте интерфейс показывает подсказку; чужой рассказ изменить нельзя |
| FR-10 | Личные истории закрыты от других участников | Подборка, публичная анкета и match не содержат текстов, названий или векторов. Список `/contexts/me` доступен только автору и также не возвращает векторы |

## Фотографии и подбор

| ID | Требование | Критерий приёмки |
| --- | --- | --- |
| FR-11 | Участник управляет галереей до шести фотографий | Добавление, замена и удаление подтверждаются в диалоге с предпросмотром. Перестановка сохраняется сразу по нажатию стрелки. Все действия доступны только владельцу; седьмой кадр отклоняется |
| FR-12 | Сервер проверяет формат и размер изображения | JPEG/PNG до 5 МиБ и 25 млн пикселей декодируется и сохраняется как JPEG с длинной стороной не более 1200 px; повреждённый или иной файл отклоняется |
| FR-13 | Чужие фотографии раскрываются взаимно | Видны первые min(своих фото, фото собеседника) снимков. Без своих фото чужие закрыты. Проверка квоты действует и по ранее выданной ссылке |
| FR-14 | Сохранённый рассказ определяет смысловое сходство | Изменение рассказа пересчитывает его вектор локальной моделью; удалённый рассказ больше не участвует в векторе участника |
| FR-15 | Подбор применяет правила допуска и единый порядок | Не выдаются сам участник, анкеты с уже оставленной им реакцией, заблокированные, скрытые, неполные и не имеющие рассказа кандидаты. Возраст кандидата соответствует диапазону смотрящего; пол — выбору обеих сторон. Свой город идёт первым; внутри групп score ↓, userId ↑ |
| FR-16 | Низкое сходство не исключает подходящего кандидата | Нулевые и отрицательные score остаются в очереди. Процент в интерфейсе основан на рассказах; город и общие теги не прибавляют к нему баллы |
| FR-17 | После новых кандидатов возвращаются собственные пропуски | `GET` не сбрасывает реакции. Запрос следующего круга удаляет только собственные Skip после исчерпания доступных непросмотренных; Like и переписка сохраняются |
| FR-18 | Участник выражает симпатию или пропускает анкету | Доступны кнопки, горизонтальный свайп и клавиатура. Ошибка сервера оставляет карточку и позволяет повторить действие; повторная сохранённая реакция возвращает 409 |
| FR-19 | Ожидание не прерывает обычное перелистывание | При загрузке следующей подборки прежняя карточка остаётся на экране; текст ожидания появляется только после 2 секунд. При ошибке запроса интерфейс не показывает успешное завершение реакции |

## Общение и контроль

| ID | Требование | Критерий приёмки |
| --- | --- | --- |
| FR-20 | Встречные симпатии создают одно взаимное совпадение | Два Like, включая конкурентные запросы, дают один match; участникам доступны чат и уведомления |
| FR-21 | Переписка доступна только участникам match | Сообщение 1–5000 символов; история порциями до 100 по курсору ID. Чужой match — 403, заблокированный — 404 |
| FR-22 | Прочтение учитывается отдельно от получения истории | GET не меняет счётчик. Подтверждение `throughId` отмечает входящие до границы; `0` только снимает ручную отметку. Новые сообщения выше границы остаются непрочитанными |
| FR-23 | Участник управляет собственным представлением чата | Закрепление, ручная отметка, очистка и скрытие не меняют настройки другой стороны. Очистка скрывает старую историю у автора; новое сообщение возвращает скрытый чат |
| FR-24 | Уведомления ведут к доступному чату | Есть уведомления о взаимности и сообщениях. Отметить прочитанным может только получатель; уведомления скрытых и заблокированных чатов не выдаются |
| FR-25 | Участник может поставить показ анкеты на паузу | Анкета исключается из подбора и закрывается новым людям, в том числе по прежним ссылкам фото. Существующие match продолжают работать. Новые реакции от скрытого участника запрещены |
| FR-26 | Участник может заблокировать и разблокировать человека | Блокировка любой стороны исключает подбор, профиль, медиа, реакции и чат для обеих. Удаление своей блокировки не снимает встречную |
| FR-27 | Участник может выгрузить собственные данные | JSON содержит собственную анкету, фото, истории, реакции, отправленные сообщения и настройки. Хеши паролей, токены и полученные сообщения не включены |
| FR-28 | Интерфейс поддерживает навигацию и доступные альтернативы | Обновление/история браузера сохраняют раздел и чат. Диалоги поддерживают клавиатуру, жесты имеют кнопочные альтернативы; уменьшенное движение отключает декоративные анимации |

## Уточнения границ

Подготовка к знакомствам в UI требует четырёх основных свойств, хотя бы одного рассказа и одного фото. Подпись может быть пустой, темы необязательны. Backend допускает подбор без фото с нулевой квотой; это правило совместимости, а не требование интерфейса.

Широкий фильтр `all` принимает любой указанный или неуказанный пол. Узкий фильтр не принимает `unspecified`. В интерфейсе вариант «людей другого пола» соответствует значению `other`, а не вычислению противоположного пола. Возрастные документы не проверяются.

Полный состав тел запросов и ограничения совместимости описаны в [API](../architecture/api-contracts.md). Не реализованные возможности перечислены отдельно в [STATUS](../STATUS.md).
