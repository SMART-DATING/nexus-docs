# Нефункциональные требования

Таблица фиксирует технические ограничения и способы проверки текущего прототипа. Она не является обещанием уровня обслуживания постоянного публичного сервиса.

| ID | Требование / ограничение | Проверка и граница |
| --- | --- | --- |
| NFR-01 | Воспроизводимый запуск | Java 21, Node.js 22.13+ для инструментов проверки, зафиксированный `package-lock.json`, Maven Wrapper; доступны H2 и Compose с PostgreSQL 16. Команды приведены в RUNBOOK |
| NFR-02 | Долговременное хранение | Аккаунты, истории, изображения, реакции и сообщения переживают перезапуск при сохранении файла H2 / Docker volume. Временные media-ticket после рестарта не сохраняются |
| NFR-03 | Изоляция данных между участниками | Проверка сессии и владельца/участника выполняется сервером. В DTO нет чужих закрытых полей, рассказов, хешей паролей и сессионных токенов |
| NFR-04 | Защита учётных данных | Пароли BCrypt; случайный 256-битный Bearer-токен живёт 24 часа, в БД хранится его SHA-256. Пароль 8–72 символа и не более 72 байт UTF-8. Транспортное HTTPS обеспечивается средой размещения |
| NFR-05 | Локальная обработка текстов | RuBERT-tiny2 запускается через ONNX Runtime CPU внутри backend; нет облачного fallback. Веса фиксированы ревизией и SHA-256. Голосовой сервис браузера — отдельный поток данных |
| NFR-06 | Ограничение ресурсоёмкого ввода | 12 историй по 20–6000 символов; 6 фото до 5 МиБ / 25 млн пикселей; 10 интересов; 5000 символов сообщения; выдача 1–50 анкет, история до 100 записей за запрос |
| NFR-07 | Целостность конкурентных операций | Уникальные пары реакций и match; согласованный порядок блокировки двух аккаунтов; лимиты галереи и историй защищены транзакциями. Есть проверки одновременных Like и запросов подбора |
| NFR-08 | Детерминированный порядок | При неизменных данных свой город → остальные, внутри групп cosine ↓ и ID ↑; порог сходства отсутствует. Выдача не является случайной выборкой |
| NFR-09 | Ограничение фоновой работы | Чат опрашивается раз в 2 с, общие уведомления/совпадения — раз в 7 с при видимой вкладке; запросы клиента ограничены 15 с. ONNX использует 2 intra-op и 1 inter-op поток, spinning отключён |
| NFR-10 | Управляемое ожидание и ошибки | При неудачной реакции карточка сохраняется; текст ожидания следующей подборки задержан на 2 с. Предусмотрены пустые состояния, повтор и обновление истёкших ссылок фото |
| NFR-11 | Адаптивность и доступность управления | Поддерживаются узкие экраны, клавиатурные альтернативы жестам, подписи кнопок, управление фокусом диалогов и `prefers-reduced-motion`. Полная сертификация WCAG не проводилась |
| NFR-12 | Проверяемость изменений | Есть компонентные тесты React, интеграционные API-проверки H2/PostgreSQL, модельные и HTTP smoke-проверки. Статус определяется конкретным запуском CI, а не числом тестов в старом отчёте |

## Производительность

Эмбеддинги сохраняются вместе с рассказами: обычное перелистывание не должно повторно выполнять модель для неизменённой версии вектора. Подбор читает метаданные галерей и не загружает двоичные изображения для всей базы. Ограничение числа SQL-запросов проверяется интеграционным сценарием.

При этом текущий алгоритм просматривает анкеты и рассказы в памяти; внешнего векторного индекса нет. Одновременные вычисления в `SemanticEncoder.encode` сериализованы. JVM heap 512 МБ в Docker не включает всю native-память ONNX. Требования к числу одновременных пользователей, p95 и общей памяти ещё не установлены измерением на целевом оборудовании.

## Эксплуатационные ограничения

Схема обновляется `ddl-auto=update`, часть логических связей не закреплена FK. Не реализованы rate limit, модерация, восстановление доступа и удаление аккаунта. Media-ticket хранятся в одном процессе; произвольное горизонтальное масштабирование требует отдельного решения. Для постоянного размещения нужны миграции, резервное копирование с проверкой восстановления, мониторинг и определённые правила обработки данных.

Эти работы перечислены в [roadmap](../roadmap.md); их наличие в плане не означает выполнение.
