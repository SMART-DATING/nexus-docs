# Нефункциональные требования и ограничения

- Java 21, Spring Boot 3.5, JPA/Hibernate, Spring Security; React 19, TypeScript, Vite.
- Пароли хешируются BCrypt. Случайный 256-битный Bearer-токен хранится в БД только как SHA-256; срок жизни 24 часа. Выход отзывает текущую сессию.
- Токен клиента хранится в sessionStorage. Cookie-аутентификации нет; CSRF выключен для Bearer API. Публичны только вход, регистрация, health и статические ресурсы. Spring Security проверяет защищённый API, сервис — принадлежность ресурсов.
- Основная целевая БД — PostgreSQL 16. Локальный режим использует H2 с файловым хранением. Схему прототипа создаёт Hibernate `ddl-auto=update`; версионированные миграции — следующий этап.
- Изменения реакции и совпадения выполняются в транзакции. Пользователи пары блокируются в порядке ID, уникальные ограничения страхуют от дубликатов.
- Списки сообщений выдаются по 100 с курсором `after`, уведомления — последние 100. Рекомендации — до 50; подбор читает пользователей в память и не предназначен для большой нагрузки.
- Чат опрашивает сервер каждые 2 секунды, уведомления — каждые 7. Это периодическое обновление, не WebSocket.
- Внешний шрифт необязателен: без сети используется системный. Фотографий нет, карточки используют декоративные аватары с инициалами.
- Демоаккаунты создаются только при `NEXUS_DEMO=true` / `--nexus.demo=true`. Они предназначены для локальной демонстрации.

Прототип не заявляет SLA, устойчивость к интернет-атакам и готовность к публичному запуску. До такого запуска нужны HTTPS, ограничение частоты входа/регистрации, восстановление пароля, модерация, резервное копирование, миграции, индексы и нагрузочные испытания. Публичные демоаккаунты при этом отключаются.
