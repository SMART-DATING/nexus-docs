# REST API

Базовый путь — `/api/v1`. JSON передаётся в UTF-8, даты/время — ISO 8601; даты рождения — `YYYY-MM-DD`. Далее пути указаны относительно базового. Контракт сверён с `ApiController`, `Requests` и сервисами backend.

## Общие правила

Защищённые методы требуют `Authorization: Bearer <accessToken>`. Исключения: health, регистрация, вход и GET фото/аватара с отдельным `access` ticket. Публичные поля анкеты доступны авторизованным участникам, а не анонимным посетителям.

Успешные методы возвращают 200, кроме создания аккаунта/рассказа/сообщения (201) и выхода/удаления рассказа (204). Конкретные коды указаны ниже.

Ожидаемая ошибка:

```json
{"status":400,"message":"Проверь поля…","timestamp":"2026-10-14T09:00:00Z"}
```

`timestamp` не гарантирован для ошибок фильтра авторизации; обработчик превышения multipart-размера может вернуть только `message`. Клиент должен учитывать HTTP status и message. Непредвиденные ошибки могут иметь стандартную форму Spring; единой схемы для абсолютно всех отказов пока нет.

| Код | Значение |
| --- | --- |
| 400 | Недопустимое тело, значение или действие |
| 401 | Неверные данные входа, отсутствующая/истёкшая/отозванная сессия |
| 403 | Чужой ресурс или запрещённый доступ к медиа |
| 404 | Ресурс отсутствует либо профиль/чат недоступен из-за видимости или блокировки |
| 409 | Занятый логин/email, повтор реакции, лимит или незавершённая подготовка |
| 413 | Слишком большой загружаемый файл |
| 503 | Невозможно сохранить рассказ без локальной модели |

## Аккаунт и сессия

| Метод | Путь | Тело / результат |
| --- | --- | --- |
| GET | `/health` | Без сессии; `{"status":"ok"}`. Не является полной проверкой готовности модели |
| POST | `/auth/register` | Регистрация; 201 и объект сессии |
| POST | `/auth/login` | Вход по login либо email; объект сессии |
| POST | `/auth/logout` | Без тела; 204, отзыв текущего токена и фото-разрешений данного пользователя |
| GET | `/users/me` | Собственный аккаунт с вложенными profile и preferences |

Регистрация из актуального интерфейса:

```json
{
  "email":"alex@example.com",
  "login":"alex_nexus",
  "password":"ExamplePassword42!",
  "passwordConfirmation":"ExamplePassword42!"
}
```

Email до 254 символов, уникален после trim/нижнего регистра. Login — 3–32 Unicode-буквы/цифры или `_.-`, сохраняется в нижнем регистре и уникален. Пароль — 8–72 символа и не более 72 байт UTF-8. При переданном login или passwordConfirmation подтверждение должно совпасть. API сохраняет совместимость с прежней регистрацией только по email/password; UI требует все четыре поля.

Вход: `{"login":"alex_nexus","password":"ExamplePassword42!"}` либо `{"email":"alex@example.com","password":"ExamplePassword42!"}`. При одновременном указании login и email поиск выполняется по login.

Объект сессии содержит `accessToken`, `tokenType:"Bearer"`, `expiresAt`, `user`. Токен непрозрачный, не JWT; 24 часа. `user` содержит `id`, `email`, `login`, `discoveryHidden`, `profile`, `preferences`. У старого аккаунта без login возвращается пустая строка. Email/login не входят в публичную анкету.

## Профиль, темы и предпочтения

| Метод | Путь | Назначение |
| --- | --- | --- |
| GET | `/profiles/me` | Собственная анкета со скрытыми полями |
| GET | `/profiles/{id}` | Доступная анкета; для своего ID — собственное представление |
| PUT | `/profiles/me` | Полное сохранение четырёх свойств, интересов и при передаче — пола |
| GET | `/interests` | Справочник: `{"items":["Музыка","Кино",…]}`; нужна сессия |
| GET | `/preferences/me` | Собственные minAge, maxAge, interestedIn |
| PUT | `/preferences/me` | Сохраняет возраст и при передаче — interestedIn |

Пример полного сохранения анкеты:

```json
{
  "properties":[
    {"name":"display_name","value":"Алекс","visible":true},
    {"name":"bio","value":"Люблю музыку и вечерние прогулки","visible":true},
    {"name":"birth_date","value":"2001-04-12","visible":false},
    {"name":"city","value":"Москва","visible":true}
  ],
  "interests":["Музыка","Кофе"],
  "gender":"unspecified"
}
```

Ровно четыре разных имени поля. Имя — непустое, публичное, до 60; город — непустой, до 80; bio — до 1000, может быть пустым; дата — возраст 18–100. Интересов до десяти, только из справочника. `gender`: male/female/other/unspecified; отсутствие сохраняет прежнее значение.

Предпочтения: `{"minAge":18,"maxAge":60,"interestedIn":"all"}`. Границы 18–100, min ≤ max. `interestedIn`: all/male/female/other; отсутствие сохраняет прежнее. `other` — отдельная категория пола.

### Представление профиля

| Поле | Содержание |
| --- | --- |
| `userId` | ID владельца |
| `properties` | Только видимые для смотрящего `{name,value,visible}` |
| `interests` | Публичные имена выбранных тем |
| `photos` | Только разрешённые `{id,position,url}`; скрытые ID/URL отсутствуют |
| `photoCount` | Полное число фото владельца |
| `photoAllowance` | Лимит для смотрящего: число его фото; для собственного профиля — 6 |
| `avatarUrl` | Первое разрешённое фото; отсутствует при нулевой доступной галерее |
| `gender` | Только в собственной анкете; null старой записи читается как unspecified |
| `contextCount`, `contextCharacterCount` | Только владельцу: количество историй и суммарная длина сохранённого текста |

## Личные истории

| Метод | Путь | Результат |
| --- | --- | --- |
| GET | `/contexts/me` | `{items,modelAvailable,modelVersion}`, только собственные истории |
| POST | `/contexts/me` | `{title,content}` → 201, сохранённая история |
| PUT | `/contexts/me/{id}` | `{title,content}` → обновлённая история и пересчитанный вектор в БД |
| DELETE | `/contexts/me/{id}` | 204, удаление собственной истории |

История: `{id,title,content,updatedAt}`. Вектор не возвращается даже в собственном списке. Название 1–60, текст 20–6000 символов после trim, всего до 12 историй. Чужая история — 403; неизвестная — 404; превышение количества — 409; нет модели при сохранении — 503. Название UI может подставить автоматически, но поле API обязательное. Эндпоинта чтения чужих историй нет.

## Галерея и изображения

| Метод | Путь | Тело / результат |
| --- | --- | --- |
| POST | `/profiles/me/photos` | Multipart `file`; добавить фото → собственный профиль |
| PUT | `/profiles/me/photos/{photoId}` | Multipart `file`; заменить своё фото → профиль |
| DELETE | `/profiles/me/photos/{photoId}` | Удалить своё фото, уплотнить позиции → профиль |
| PUT | `/profiles/me/photos/order` | `{"ids":[3,1,2]}`; все собственные ID ровно один раз → профиль |
| GET | `/photos/{id}?access={ticket}` | Бинарное разрешённое изображение |

Допускаются JPEG/PNG до 5 МиБ и 25 млн пикселей. Сервер проверяет содержимое, перекодирует в JPEG без исходных метаданных, уменьшает длинную сторону до 1200 px. Галерея до шести кадров; лишний — 409, чужое изменение — 403, неверный порядок — 400.

Чужой профиль выдаёт первые min(число фото смотрящего, число фото владельца) снимков. Временный ticket действует 15 минут; при чтении проверяются его срок, ID/версия фото, доступность анкеты и актуальная квота. Выход отзывает фото-разрешения пользователя; рестарт процесса теряет их все. Замена кадра меняет версию. Без ticket, при истечении или утрате квоты — 403; удалённое фото при ещё распознанном ticket — 404.

Заголовки изображения: `Cache-Control: private, no-store`, `X-Content-Type-Options: nosniff`; тип `image/jpeg` либо `image/svg+xml` для служебных иллюстраций. Скопированный действующий URL является временным разрешением. Клиент может обновить разрешённые URL повторным GET профиля с Bearer-сессией.

## Подбор и реакции

| Метод | Путь | Назначение |
| --- | --- | --- |
| GET | `/recommendations?limit=20` | Текущие непросмотренные кандидаты; не сбрасывает реакции |
| POST | `/recommendations/next?limit=20` | Та же очередь; при полном исчерпании может сбросить только свои Skip |
| POST | `/recommendations/restart` | Явный сброс только своих Skip → `{"restored":2}` |
| POST | `/users/{id}/like` | Сохранение Like |
| POST | `/users/{id}/skip` | Сохранение Skip |

`limit` ограничивается 1–50; по умолчанию 20. Ответ GET: `{items,skippedCount}`; POST next дополнительно содержит `cycleRestarted:boolean`.

Элемент items — публичный профиль плюс:

| Поле | Значение |
| --- | --- |
| `compatibilityScore` | Косинусное сходство [-1,1] |
| `commonInterests` | Пересечение публичных тем; не компонент score |
| `matchingBasis` | `semantic` |
| `remainingCount` | Число оставшихся от этой позиции во всей очереди, включая текущую |
| `similarityFloor` | Поле совместимости 0,10,…,90; вычисляется из score и не является фильтром |

Свой город первым, остальные после него; внутри групп score ↓, ID ↑. Возраст проверяется по выбору смотрящего, пол — по выбору обеих сторон. Неполные/скрытые/заблокированные/не имеющие рассказа и уже оценённые кандидаты не выдаются. Низкое, нулевое и отрицательное сходство не исключается. [Точный алгоритм](MODEL.md).

Нет четырёх собственных свойств или рассказа — 409. Нет подходящих анкет — 200 с пустым items. POST next сбрасывает Skip только когда непросмотренных нет, а подходящие пропущенные есть; Like, match и сообщения остаются.

Результат реакции: `{"liked":true,"skipped":false,"matched":true,"matchId":15}`. Без взаимности matched=false и matchId=null. Самореакция — 400, повтор сохранённой реакции — 409, неизвестный/недоступный пользователь — 404, собственная пауза — 409. Прямой метод реакции проверяет заполненность базового профиля, видимость и блокировку; фильтры и наличие рассказа применяются при формировании выдачи. Это не следует считать одним и тем же набором проверок.

## Match и сообщения

| Метод | Путь | Назначение |
| --- | --- | --- |
| GET | `/matches` | `{items:[match]}`; закреплённые первыми, затем ID ↓; личные скрытые и заблокированные исключены |
| GET | `/matches/{id}` | Один доступный match |
| GET | `/matches/{id}/messages?after=0` | Первые 100 сообщений с ID выше after и личной границы очистки, по ID ↑ |
| POST | `/matches/{id}/messages` | `{"text":"Привет!"}` → 201, сообщение |
| PATCH | `/matches/{id}/read` | `{"throughId":42}` → `{"unreadCount":0}` |
| PATCH | `/matches/{id}/settings` | `{"action":"pin"}` → актуальный match |

Match: `{id,user,createdAt,unreadCount,pinned,markedUnread,clearedThroughId,lastActiveAt}`. `user` — доступный профиль собеседника, не аккаунт. `lastActiveAt` — его последний авторизованный запрос или null; запись обновляется не чаще раза в 30 с. UI считает период до 75 с признаком недавней активности, а не доказательством непрерывного соединения.

Сообщение: `{id,matchId,senderId,text,createdAt,readByRecipient}`. Text — 1–5000 символов; внешние пробелы удаляются. Для продолжения истории передаётся последний полученный ID. GET ничего не отмечает прочитанным.

`throughId` обязателен и ≥0. Подтверждаются только входящие сообщения до этой границы; новые выше неё не меняются. Ноль снимает ручную отметку без подтверждения сообщений. `unreadCount` — входящие после личной очистки, с минимумом 1 при markedUnread.

Настройки:

| action | Действие только для текущего участника |
| --- | --- |
| `pin` / `unpin` | Закрепить / открепить; pin также снимает личное скрытие |
| `unread` | Включить ручную отметку непрочитанного |
| `read` | Снять отметку и подтвердить текущие входящие до максимального ID |
| `clear` | Скрыть сообщения до текущего максимального ID и снять ручную отметку |
| `delete` | Скрыть чат из списка, снять закрепление и ручную отметку |

Clear/delete не удаляют общие строки сообщений. Новое сообщение от любой стороны снимает скрытие чата у обеих. Настройки собеседника не возвращаются. Для чужого match — 403, отсутствующего/заблокированного — 404; неизвестное действие — 400.

## Уведомления

| Метод | Путь | Результат |
| --- | --- | --- |
| GET | `/notifications` | `{items:[{id,userId,matchId,text,seen,createdAt}]}` |
| PATCH | `/notifications/{id}/read` | То же уведомление с seen=true |

Выборка берёт до 100 последних собственных уведомлений по ID ↓, затем исключает скрытые/заблокированные чаты. Чужая отметка — 403. Уведомление о сообщении не содержит его текста.

## Видимость, блокировки и выгрузка

| Метод | Путь | Тело / результат |
| --- | --- | --- |
| PUT | `/users/me/discovery` | `{"hidden":true}` → `{"hidden":true}` |
| POST | `/users/{id}/block` | Идемпотентно создать собственную блокировку → `{"blocked":true}` |
| DELETE | `/users/{id}/block` | Снять только собственную блокировку → `{"blocked":false}` |
| GET | `/users/me/blocks` | `{items:[{userId,displayName,createdAt}]}` |
| GET | `/users/me/data` | Собственная JSON-выгрузка, `Content-Disposition: attachment`; no-store |

Пауза скрывает анкету и фото от новых людей, но сохраняет доступ существующим match. Собственные новые реакции запрещены. `hidden` обязателен. Снятие паузы возвращает показ без удаления данных.

Блокировка любой стороны закрывает обеим подбор, профиль, фото, реакции и существующий чат; прежние фото-ссылки тоже перестают работать. Самоблокировка — 400. Снятие своей блокировки не отменяет встречную. История и match физически сохраняются.

Выгрузка содержит `formatVersion:1`, `exportedAt`, `account`, `photos`, `privateContexts`, `reactions`, `sentMessages`, `blockedUsers`, `chatPreferences`. Фото — `{position,contentType,base64}`. Сессионные/медийные токены, хеши паролей и полученные сообщения исключены. Полные собственные фото могут сделать файл большим; пагинации выгрузки нет.

## Совместимость

- `POST /profiles/me/avatar` заменяет первое собственное фото или создаёт его; multipart file.
- `DELETE /profiles/me/avatar` удаляет первый снимок без автоматического восстановления.
- `GET /avatars/{id}?access={ticket}` читает первое фото пользователя с таким же контролем доступа.
- `GET /match/{id}` — alias получения match, не отдельный объект.
- Старые аккаунты без login входят по email; null пола/предпочтения читается как unspecified/all.

## Маршруты клиента

Это страницы React, а не API: `/` — главная до входа и знакомства после него; `/#login`, `/#register` — формы; `/#matches` — чаты; `/match/{id}` — конкретная беседа; `/#profile` — анкета; `/#profile/photos` — фото; `/#profile/story` — «Для подбора»; `/#notifications` — уведомления.
