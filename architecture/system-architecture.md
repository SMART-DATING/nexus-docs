# Архитектура системы

Nexus — веб-приложение с React-клиентом и модульным Spring Boot backend. Подбор, сообщения, хранение данных и локальная модель выполняются одним backend-процессом. Отдельных микросервисов, очереди сообщений и внешнего векторного хранилища нет.

| Сервис распознавания браузера | Необязательный голосовой ввод при поддержке среды | Web Speech API; возможна внешняя обработка звука |

## Слои backend

1. `SecurityConfig` проверяет Bearer-сессию защищённых API-маршрутов. Изображения получают отдельное временное разрешение в URL.
2. `ApiController` связывает HTTP с DTO и валидацией. `Errors` формирует ожидаемые ошибки.
3. `NexusService` выполняет операции аккаунта, профиля, предпочтений, подбора, реакций и чатов.
4. `ContextService`, `GalleryService`, `BlockService`, `DataExportService`, `PresenceService` выделяют операции с историями, медиа, блокировками, экспортом и активностью.
5. JPA-репозитории обращаются к 14 таблицам. `SemanticEncoder` вызывает локальную модель непосредственно из процесса Java.

`NexusService` пока объединяет несколько предметных областей. Это фактическая структура прототипа; независимые сервисы авторизации и сообщений не заявляются. [UML компонентов](../diagrams/UML.md).

## Основные потоки

**История.** Автор подтверждает текст → API проверяет владельца и длину → модель строит вектор → история, версия модели и вектор сохраняются. Подбор читает сохранённые векторы; изменение версии модели вызывает их обновление при чтении. Чужому клиенту текст и вектор не выдаются.

**Подбор.** Backend читает необходимые данные анкет и рассказов, исключает неподходящих кандидатов, вычисляет cosine, группирует по городу и сортирует. Галереи и разрешения на фото формируются только для выдаваемой страницы. Изображения всей базы в процессе ранжирования не загружаются. [Алгоритм](MODEL.md).

**Взаимность.** Реакция сохраняется в транзакции. При встречном Like создаются match и два уведомления. Аккаунты пары блокируются в порядке возрастания ID; уникальные ограничения препятствуют дубликатам. Сообщения также проверяют участие и блокировку. [Последовательности](../diagrams/sequences.md).

**Медиа.** Клиент получает только разрешённые ID/URL. Случайный ticket действует 15 минут и связан со смотрящим, фотографией и её версией. При чтении заново проверяются квота, порядок, видимость и блокировка. Ticket — переносимое временное разрешение; защита от копирования уже показанного фото не обеспечивается.

**Чат.** REST polling, без WebSocket: открытая видимая переписка опрашивается раз в 2 с, общие match/уведомления — раз в 7 с. История приходит порциями до 100 сообщений. Отдельное подтверждение прочтения ограничено `throughId`; GET не отмечает сообщения прочитанными.

## Данные и границы доверия

База отделяет аккаунт, поля анкеты, интересы, личные истории, фото, реакции, match и сообщения. Профиль и чат — представления этих данных, а не отдельные таблицы. [ERD](../diagrams/ERD.md) и [словарь данных](data-dictionary.md).

Проверка владельца и квоты выполняется сервером; интерфейс не считается границей безопасности. Скрытые поля отфильтровываются до отправки. Пауза анкеты сохраняет доступ существующим match, блокировка любой стороны — закрывает его. Подробнее: [данные и приватность](../privacy/data-handling.md).

## Варианты развёртывания

| Режим | HTTP-путь | Хранение | Назначение |
| --- | --- | --- | --- |
| Разработка | Браузер → Vite `5173` → backend `8080` | Файловая H2 по умолчанию | Изменение и проверка клиента/API |
| Compose | Браузер → nginx `8088` → backend → PostgreSQL | Именованный volume | Совместный воспроизводимый запуск трёх компонентов |
| Единый JAR | Браузер → Spring Boot `8080`, React встроен | Файловая H2 либо заданная БД | Демонстрация без npm и отдельного frontend-сервера |

По умолчанию опубликованные порты привязаны к loopback. Внутри Docker backend слушает `0.0.0.0` для nginx. Постоянный публичный домен и автоматически настроенный HTTPS в исходниках отсутствуют. [Команды запуска](../RUNBOOK.md).

## Принятые решения и последствия

| Решение | Причина | Последствие |
| --- | --- | --- |
| Один backend | Меньше компонентов для запуска и отладки | Общие ресурсы процесса; дальнейшее разделение требует измеренной потребности |
| Локальная готовая модель | Нет отправки историй в внешний inference API | Веса и native-runtime нужно доставлять вместе со средой; CPU и память расходуются локально |
| Изображения в БД | Общие права доступа и простой перенос демонстрации | Рост БД; при росте нагрузки потребуется отдельное хранение |
| Ticket в памяти процесса | Простой доступ из `<img>` без сессионного токена в URL | Рестарт отзывает ссылки; несколько экземпляров требуют общего решения |
| Hibernate `ddl-auto=update` | Быстрое развитие прототипа | Нет управляемой истории миграций и отката схемы |
| REST polling | Простой клиент и HTTP-инфраструктура | Задержка сообщений зависит от интервала; число запросов растёт с активной аудиторией |

Полный поиск по данным в памяти подходит текущему объёму, но не доказывает готовность к большой аудитории. Нагрузочные характеристики, миграции и постоянная эксплуатация — отдельные задачи [roadmap](../roadmap.md).
